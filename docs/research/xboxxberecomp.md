# XboxXBERecomp (TGP482) as the toolchain for MK:DA / MK:D / MK:A native ports

Source read: `external/XboxXBERecomp` (shallow clone, upstream `https://github.com/TGP482/XboxXBERecomp`, `SDK_VERSION` 0.1.0).
All paths below are relative to that folder unless stated. Line numbers are from the clone on 2026-10-24.

## 0. Headline: XDK 4721 / 5849 availability

- `xdk/` holds exactly two builds: `xdk/4831/{layout.toml,signatures.toml}` (5.3 KB / 58 KB) and `xdk/5849/{layout.toml,signatures.toml}` (5.4 KB / 86 KB). Nothing else.
- **5849 is present.** MKD and MKA link every library at 1.0.5849 (`research/mkd/xbe_info.json`, `research/mka/xbe_info.json`: XAPILIB, D3D8, D3DX8, XGRAPHC, XBOXKRNL, XONLINES, LIBCMT, LIBCPMT, DSOUND, XVOICE, VOICMAIL). `xbe_symbols` will pick `xdk/5849` for both.
- **4721 is absent.** MKDA (`research/mkda-rev1/xbe_info.json`, all libs 1.0.4721, plus XMV) will stop at `SignatureDir()` (`tools/symbols/main.cpp:1016-1029`): "no signatures for these library builds; available: 4831 5849", and `Scan()` returns 1 (`main.cpp:1361-1364`). The build picked is the D3D8/D3D8LTCG/XAPILIB build first, then any library's build (`main.cpp:1005-1013`).
- Which titles proved the shipped sets: `xdk/5849/layout.toml:1-2` "proven by the default.xbe (Splinter Cell Double Agent) ... sc4_adv.xbe matches", with BLACK addresses cross-referenced at lines 14, 21, 29, 33-35, 42 (so SCDA and BLACK are 5849). `xdk/4831/layout.toml:1-2` "proven by the default.xbe (007: NightFire) ... Driving.xbe (same 4831 libraries)". `runtime/xdk/dsp_image.cpp:4-5` lists "every 5849 image seen (HL2, Double Agent, Black, 007)", so the 007 attribution is inconsistent inside the repo; the README names the third port as 007: From Russia With Love.

### What generating 4721 requires
- Signatures are **not** made from XDK `.lib` files. `README.md` ("A new XDK build needs `xdk/<build>/layout.toml` and signatures made from titles whose configs are complete") and `main.cpp:1415-1427`: `xbe_symbols --sign <config.toml>... --out signatures.toml [--skip name,...]`. Input = one or more *finished* game configs on that build whose `[symbols]`/`[data]` addresses were filled by hand (Ghidra via `tools/symbols/xbe2pe.py`). The file stores lengths, masked FNV hashes, callee hashes two levels deep, constants (`k`), ret bytes and read-before-write registers (`xdk/5849/signatures.toml:1-13`); no library bytes.
- Name set to fill for 5849: 243 `[symbols]` (103 D3D, 65 DSOUND, 34 XNET, 15 .text/CRT, 6 XPP, 4 BINK, 2 XONLINE), 3 `[anchors]`, 12 `[data]` (D3D_Device, D3D_pDevice, D3D_DirtyFlags, D3D_IndexData, D3D_RenderState, D3D_DeferredTextureState, D3D_SimpleRenderStateEncode, D3D_Streams, DSound_StreamVtable/2, XPP_GamepadType, XPP_MemoryUnitType). Only 3 names have no signature (`D3DDevice_BeginPush`, `D3DDevice_EndPush`, `D3DDevice_SetPalette`); 102 carry an `.XTLID` fallback id.
- `layout.toml` per build: ~45 CDevice/DSound/XPP struct offsets, each justified by a disassembly address (`xdk/5849/layout.toml:5-52`). `runtime/xdk/layout.h:2-3,33-37`: a missing key aborts at first use ("is unknown for this image, add it to the config") rather than guessing.
- Bootstrap trick for MKDA: copy `xdk/4831` to `xdk/4721` (signatures are masked hashes; 4721 and 4831 are both 2002-era libs so many D3D/DSOUND bodies will match byte-for-byte), run the scan, then resolve the misses in Ghidra and `--sign` a real 4721 set from the completed MKDA config.

## 1. Pipeline end to end

**xbe_symbols -> config/game.toml** (`tools/symbols/main.cpp:1352-1398` `Scan`): prints title id and library versions (`:999-1003`), picks the signature dir, sweeps code sections chosen by `GuessCode` (`:969-980`: every *executable* section except `.rdata .data .data1 .XTLID DOLBY XON_RD dsstdfx`, `$$*`, `*DATA`), matches by bytes, then by constants for the rest, checks calling conventions (LTCG `[abi]`), resolves `[data]` via instruction operands or `.XTLID`, prints "found N of M functions, K of L data" and "missing (0, the host traps if the game calls one)" (`:1293-1315`). `Partitions()` doubles from 8 until ~60 KB code per file, max 256 (`:1317-1330`). Output table (`:1332-1346`): `[xbe] path/title/entry/xdk=<build>/out/partitions/code_sections/library`, `[functions]`, `[symbols]`, `[data]`, `[abi]`. Omit `--out` to print to stdout (`:1395`).

**game.toml extras** (`tools/recomp/main.cpp:43-52`, template `templates/game/config/game.toml:11-31`): `[xbe] data_ranges` (bytes in code sections that are never code), `[xbe] trace` (log calls of listed functions), `[[hook]] at/call/after/on_true/on_false`, `[[function]] at/end`, `[[switch]] at/targets`, `[abi] name = ["esi","stack"]`. `[xbe] xdk = N` includes `<sdk>/xdk/N/layout.toml` (`main.cpp:62-74`).

**xbe_recomp** (`xbe_recomp <config.toml> [xbe] [out] --xdk <sdk>/xdk`, `main.cpp:205`). Analysis (`analysis.h:63-107`, `analysis.cpp`): Zydis decode; walk from entry, `[symbols]`, `[[function]]`; `SeedPointers` treats code-pointing immediates as callbacks (`:511`); `Adopt` direct calls (`:544`); `GapFill` (`:467`); `EhContinuations` (`:581-583`: MSVC `mov eax, FuncInfo; jmp __CxxFrameHandler` frames, catch blocks returning the resume address in eax); jump tables `ReadTable` incl. `neg idx` backwards tables (`:57-76`) and `SledTable` for memcpy movsd sleds (`:147-149`). Codegen per function (`codegen_emit.cpp:33-124`): emits `X86_FUNC(__imp__sub_XXXXXXXX)` with `X86_LOAD_FLAGS()`, labels + `goto`, `try { } catch (const X86Resume&)` when the body writes `fs:[0]` (`:96-98,118-120`), then `X86_WEAK_FUNC(sub_X, __imp__sub_X)` (`:122`). Direct call = `X86_PUSH32(ret); sub_T(ctx, base)`; unknown target = `x86_icall`; kernel thunk slot = `x86_kernel(ctx, base, ordinal)` (`codegen.cpp:234-256`); table jumps become `switch` with an `x86_icall` default (`:267-276`); backward `jmp` gets a compiler barrier so spin loops reread memory (`:260-262`); `rdtsc`/`cpuid` go to `x86_rdtsc`/`x86_cpuid` (`codegen_int.cpp:465-468`); privileged ops are logged once (`x86_priv`). Flags are C++ locals; only tail calls store them in `ctx` (`runtime/cpu/x86_context.h:13`). x87 is `double st[8]` + `top` with precision control honoured (`x86_ops.h:67,91`), MMX `mm[8]`, SSE `xmm[8]` (`x86_context.h:19-22`). Files written (`codegen_emit.cpp:200-320`): `x86_recomp.<p>.cpp` partitioned by instruction weight, `x86_func_mapping.cpp` (`X86FuncMappings`, `X86Continuations`, `X86CodeBase/End`, `X86EntryPoint`, trap bodies for symbols absent from this image), `image_symbols.h` (`SYM_x`, `HAS_x`, `XDK_x`, `IMAGE_ABI`), `x86_recomp_shared.h`, `hook_exports.h`, `exports.def`/`imports.def`, `x86_recomp_stats.txt` (function/instruction counts and "unimplemented <mnemonic> N").

**Guest memory model** (the part that matters for rollback): every recompiled function is `void(X86Context&, uint8_t* base)` and memory access is `*(T*)(base + (uint32_t)va)` (`x86_ops.h:16-22`). `mem::Init` reserves one 4 GB host region (hint `0x100000000`, `runtime/kernel/memory.cpp:31-72`); a 64 MB file mapping is the console's physical RAM, mapped twice at `0x80000000` and `0xF0000000` (`memory.h:9-11`); user VA `0x10000..0x7FFE0000` is committed on demand with a per-page map `g_committed` (`memory.cpp:74-95`); system/pool area `0xB0000000` (KPCR, ETHREAD, host-side tables; `memory.h:14`), guest stacks at `0xD0000000` with guard pages (`memory.h:16`, `memory.cpp:386-396`), kernel variables in the first physical MB (`memory.h:12`, `cpu/dispatch.cpp:190-201`). The XBE is copied to its own base and preload sections marked loaded (`kernel/boot.cpp:106-115`). So image, heap, stacks, TLS (top of each stack, `threads.cpp:36-37`), KeTickCount, D3D push scratch and all D3D/DSound resource memory are inside one flat arena addressed by `base + va`. Host-side state the guest references by handle or pointer: kernel `Object`s (events/mutants/semaphores/timers/threads/files) are `shared_ptr`s keyed by handle or by the guest dispatcher header (`kernel/objects.cpp:36-125`, `kernel.h:103-127`), sockets (`xdk/xnet.cpp:70-73`), DSound voices, `gpu::State` and D3D12 resources, per-thread `X86Context` (a local on the host thread, `threads.cpp:160-161`).

**Overrides and hooks**: a strong `X86_FUNC(sub_X)` replaces the weak alias (`x86_ops.h:29,44-45`; `templates/game/src/game/hooks.cpp:1-8`); `__imp__sub_X` is the original. `xdk/hle.h:11-13` gives `SYM(name)`, `GUEST(name)`, `GUEST_ORIG(name)`; `HLE_STDCALL/FASTCALL/CDECL/WRAP` (`hle.h:110-139`) and `GUEST_CALL` (`:142-147`) handle argument maps. `[[hook]]` emission (`codegen_emit.cpp:177-199`): flags saved to `ctx` before, reloaded after; `on_true/on_false` can `ret` (pops the function's `ret n`) or jump to another instruction of the same function. Hooks are exported from the exe by decorated name (`:239-245`).

**Player-side first launch** (`runtime/app/game_code.cpp:1-4`): a release ships no game code; `xbe_recomp.exe`, `clang.exe`, `lld-link.exe`, configs, layouts and the two CPU headers live in `compiler/` (`cmake/XbeRecomp.cmake:26-51`). On start the exe runs `xbe_recomp` (`:297-313`), then clang per partition with `-target x86_64-pc-windows-msvc -fms-compatibility-version=19.40 -std=c++20 -O2 -march=x86-64-v2 -fno-strict-aliasing -DNDEBUG -DX86_GAME_CODE -nostdinc -nostdinc++ -w` (`:47-52`), one job per logical CPU bounded by 512 MB each (`:226-234`), then `lld-link /dll /noentry /nodefaultlib /machine:x64 /opt:noicf /def:exports.def` (`:52,383-392`) into `<exe>.dll`, which the exe delay-loads (`XbeRecomp.cmake:121-122`) and whose CRT calls are forwarded to `vcruntime140`/`ucrtbase` (`cpu/dispatch.cpp:31-47`). Finished objects survive a crash (`:3-4`), ~1 GB disk needed (`:53`), progress window with cancel. The exe verifies the player's XBE SHA-1 against `kImageSha1` baked at build time (`app/game_files.cpp:21,80-83`; `XbeRecomp.cmake:106-111`) and warns on "another release".

## 2. Runtime surface

- **Kernel**: 265 exports registered (`runtime/kernel/xboxkrnl.cpp` 203, `rtl.cpp` 43, `files.cpp` 19) against a 379-name ordinal table (`ordinals.cpp:6-88`). Missing imports are logged at boot (`boot.cpp:121-133`) and trap on call (`dispatch.cpp:173-181`). Covered: Av* (saved data address for quick reboot), Ex pool and EEPROM settings (`xboxkrnl.cpp:1223-1279`: English, NTSC-M, North America, stereo, 480p + widescreen flag), Hal*, Interlocked*/SList, Ke* events/semaphores/mutants/timers/DPCs/waits/APCs/IRQL/priorities, Mm* contiguous/system/virtual, Nt* VM/files/sync, Ob*, Ps* threads, Rtl* strings/unwind, Xc* crypto (SHA-1, RC4, HMAC, PKCS1 verify, ModExp; DES is a plain copy, `:1327`), Xe* sections, console keys, LaunchDataPage, quick reboot via process relaunch (`boot.cpp:176-215`). NT-style exception dispatch through the `fs:[0]` chain and `RtlUnwind` (`xboxkrnl.cpp:1019-1061`). Not covered: IRP-based I/O manager (`:1280`), anything in `ordinals.cpp` not in the export list.
- **Files / discs / saves**: `NtCreateFile..NtQueryDirectoryFile` over host folders with case-insensitive lookup (`files.cpp:40-95,324-770`). `D:` = game folder or a mounted disc image; `\Device\Harddisk0\Partition1..5` = `<exe dir>\hdd\{E,C,X,Y,Z}` (`files.cpp:193-209`, `app/main.cpp:293-296`, `hddN` per `--instance`), so saves land in `hdd\E`. Disc images: whole dump or xiso, `MICROSOFT*XBOX*MEDIA` at partition 0 or `0x18300000`, read-only (`kernel/disc.h:2-3`, `disc.cpp:25-29`). The SCSI pass-through reports an authenticated disc (`files.cpp:716-731`).
- **D3D8** (`runtime/xdk/d3d8.cpp:1-2`): ~85 HLE entry points (CreateDevice, Reset, Swap, Clear, Draw*/Begin/End, SetTexture/Stream/Indices/Transform/Viewport/RenderTarget, shaders, fences, Lock2DSurface, BeginPush/EndPush/RunPushBuffer, SetTile/GetTile, PersistDisplay, gamma, palettes); "Resource creation, locking and the XG helpers stay recompiled: they only manage memory". Inlined immediate-mode and raw push-buffer writes are parsed from a scratch buffer (`:156,1218-1442`). Vertex programs, pixel combiners and fixed function go to HLSL (`gpu/shaders.h:43-61`); render targets/depth are D3D12 targets keyed by guest surface (`gpu/ext.h:24-39`); occlusion queries back visibility tests; render thread records calls and reads vertex/texture memory later, fences/locks wait on it (`gpu/render_thread.cpp:1-4`), Present keeps one frame in flight (`:186-187`). `gpu::Extension` (`ext.h:63-98`) lets a port change target format/scale, add passes and shader snippets. D3D field offsets come from `layout.toml`, globals from `[data]` (`d3d8.cpp:86-90`). A 60 Hz host thread emulates the vblank interrupt, event and callback (`d3d8.cpp:294-318`).
- **DSound** (`dsound.cpp:1`: "XDK 4831 and 5849 on a host software mixer"): buffers and streams read guest memory as they play; Xbox ADPCM (`:199,215-247`), 32 mix bins (`dsp_image.h:9`), 3D voices with interaural delay (`:327-460`), stream packet callbacks run in `DirectSoundDoWork` (`:174-175`), I3DL2 listener. **Effects image**: `XAudioDownloadEffectsImage` loads it from a named XBE section when flag bit 0 is set, else from a game file (`:898-910`); `IDirectSound_DownloadEffectsImage` takes it from memory (`:913-918`). `dsp_image.cpp:1-6,42-99` decrypts the DSP code with DSOUND's LFSR cipher and recognises effects by code hash: gain, mixer, filter, I3DL2 reverb, crosstalk are reproduced; SRC/DMA effects are "left out and logged". Output is stereo float 48 kHz through XAudio2 (`audio/xaudio2.cpp:26-31`); speaker bins are downmixed (`dsound.cpp:274-277`). Not reproduced: envelopes (`:995`), StopEx release (`:984`). Nothing reads the DOLBY section (the AC-3 encoder data); `GuessCode` treats DOLBY and XON_RD as data (`main.cpp:970`).
- **XAPI** (`xdk/xapi.cpp`): `XInitDevices` (port poller thread, 250 ms), `XInputOpen/Close/GetState/SetState/GetCapabilities`, `XMountUtilityDrive`, `XLaunchNewImageA` (only recompiled images; dashboard launches refused `:154-165`). Everything else in XAPILIB (save games, XGetVideoFlags, XFindFirst...) runs recompiled on top of the kernel.
- **XNet / XOnline** (`xdk/xnet.cpp:1-10`): System Link on host Winsock. 34 XNET symbols: XNetStartup, key create/register, GetTitleXnAddr (the XNADDR `ina` is the real IPv4, so secure addresses map 1:1, `:336-342,404-435`), DNS, full BSD socket set plus `WSASend/Recv*` overlapped with a pump thread (`:304-334`). Broadcasts are fanned out to `join_ip` (settings, `app/app.h:26`), to public peers seen, and NAT-rewritten ports are remembered (`:234-267`). `--instance N` binds `127.0.0.N` for two copies on one PC (`:148-158`; `app/main.cpp:182-188`). **XOnline is stubbed only at the edges**: `XOnlineStartup`/`XOnlineCleanup` return 0 (`:378-379`); the title's XNet object stays null so other XOnline calls fail with `XONLINE_E_NOT_INITIALIZED` (`:2-3`). No XVoice/VOICMAIL names exist in the signatures or runtime (grep: 0 hits).
- **Input**: SDL3 gamepads only, 4 ports, lowest free port on plug-in, WGI + HIDAPI (`core/input.cpp:58-81`); `GameInfo::pad(port, Pad&)` rewrites every polled pad (`:112`) and `GameInfo::rumble` the motors (`:131`). Keyboard/mouse is per port, not in the SDK.
- **Timing / CPU identity**: `x86_rdtsc` = `steady_clock` scaled to 733,333,333 Hz (`cpu/dispatch.cpp:278-285`); `x86_cpuid` = GenuineIntel family 6 model 8 (Coppermine), `fpu tsc cx8 cmov mmx fxsr sse` (`:287-305`); KeTickCount/KeInterruptTime/KeSystemTime refreshed by a 1 ms host thread (`xboxkrnl.cpp:105-116`); `KeQueryPerformanceCounter` (`:238`); timers on a host `TimerLoop` thread (`objects.cpp:352-384`), DPCs on a "dpc" host thread (`:348`); `app::Pace()` fps cap inside `D3DDevice_Swap` (`d3d8.cpp:603`, `main.cpp:223-241`).

## 4. Determinism and netplay hooks for rollback

- **Threads = host threads.** `PsCreateSystemThreadEx` spawns a real OS thread with a 64 MB host stack (`kernel/threads.cpp:99-122,141-184`); guest stack/TLS/KPCR/ETHREAD live in the arena (`:29-54`) but the recompiled frames, locals and the per-thread `X86Context` live on the host stack. Priorities are stored, not applied (`xboxkrnl.cpp:868-884`); suspension is cooperative at kernel waits/yields (`kernel.h:175`). Scheduling is therefore the host's, and every cross-thread race in the game is real. This is the main rollback risk: a snapshot is only coherent when every guest thread that touches simulation state is parked at a known point.
- **Host threads that write or read guest memory concurrently**: tick thread (`xboxkrnl.cpp:105-116`), timer loop, dpc thread, vblank thread (`d3d8.cpp:294`), XAPI port poller (`xapi.cpp:65-71`), XNet pump, audio render (reads voice memory as it plays, `dsound.cpp:1`), render thread (reads vertex/texture memory after the call returns, `render_thread.cpp:1-4`). Restoring memory under them needs `g_backend->Flush()` and a DSound lock at minimum.
- **No virtual time.** rdtsc, KeTickCount, interrupt/system time, performance counter, vblank and timers all derive from `steady_clock` (refs above). A rollback build must replace `x86_rdtsc`, `InterruptTime`/`Now100ns` (`xboxkrnl.cpp:109-113`, `objects.cpp:175-180`), the tick thread and `VerticalBlank` with a frame-stepped clock.
- **Frame boundary candidates**: `D3DDevice_Swap` HLE (`d3d8.cpp:578-617`, on the title's render thread, already calls `app::Pace()`); the vblank callback; `GameInfo::ui` per present (`gpu/d3d12.cpp:2866`); a `[[hook]]` at the engine's tick or input-read instruction, with `on_true = "ret"` to skip a frame; or an `X86_FUNC` override of the game's input-poll function. Inputs are cleanest through `GameInfo::pad` (`input.cpp:112`), which already sits between SDL and `XInputGetState`.
- **Snapshotting**: all guest-visible bytes are in one arena, so a state = committed user pages (`g_committed`, `memory.cpp:75`; reservations `g_reserved`), the 64 MB physical window, the system area and the stack area, plus the parked threads' `X86Context`s. Host-side state that must be versioned or frozen too: kernel object signal/owner state (`objects.cpp`), the handle table, pending timers/APCs, file positions, DSound voices, `gpu::State`, the guest-side D3D reference bits (`d3d8.cpp:122-123`). Rolling back only the fight simulation (heap + `.data` + main thread stack) while treating audio/render/streaming as non-rolled-back side effects is the realistic design; MK's engine layout decides how feasible that is.
- **System Link pieces reusable for a session layer**: the socket table, pump thread, overlapped completion, NAT/broadcast fan-out, `join_ip` setting and `--instance` loopback (`xnet.cpp:52-158,234-334`; `app/main.cpp:182-188`); the harness runs N instances as peers (`run.sh:2-6`). The SCDA port plays co-op/versus by direct IP with UDP port forwarding. MK's own System Link netcode would stay lockstep; rollback would bypass it by injecting inputs at the pad layer and using the socket layer only as transport.

## 6. Assessment for MK

**Blockers / risks, in order**
1. **MKDA = XDK 4721, unsupported.** Needs a 4721 `layout.toml` and `signatures.toml` authored from MKDA itself (section 0). MKDA also carries `XMV` (WMV movies) which the SDK has no HLE for; it may run recompiled on CPU through DSound streams and D3D textures, untested.
2. **MKD/MKA = 5849, supported**, but their executable-flagged `PSGSFD00/_I/_B/_P` (MKD) and `PSFD*` (MKA) shader-data sections will be swept as code by `GuessCode` and listed in `code_sections` (predicted: `['.text','D3D','D3DX','XGRPH','PSGSFD00','PSGSFD_I','PSGSFD_B','PSGSFD_P','XNET','XONLINE','DSOUND','XPP']`). Remove them from `code_sections` (or `data_ranges`) before `xbe_recomp`. MKA has `.XTLID` (helps matching); MKD does not.
3. **XONLINE/XON_RD (155-254 KB) and XVOICE/VOICMAIL** are recompiled as-is with no host side. Expect the Xbox Live menu to fail "not initialised" at best; any XOnline/XVoice call on the boot path or in the versus lobby must be found in the log and overridden with `X86_FUNC`. Rollback netplay does not need them.
4. **dspimage / DOLBY**: `dspimage` (18.6 KB, inserted section) is the title's effects image; if MK loads it with `XAudioDownloadEffectsImage(..., flags&1)` from the section, the SDK decrypts and runs the recognised effects (`dsound.cpp:898-910`, `dsp_image.cpp:78-99`); unknown effect kinds are logged, not fatal. DOLBY is unused: stereo only. Low risk.
5. **Midway engine specifics**: custom vertex programs and combiners (coverage is proven on three Ubisoft/Criterion/EA titles, not Midway's renderer); `D3DDevice_BeginPush/EndPush` have no 5849 signature (found only by `.XTLID`/constants) and trap if MK pushes raw commands through them and they are left at 0; `LIBCPMT` C++ exceptions are supported. MKD/MKA have no BINK section, so their FMV path is unknown and may need a hook.
6. **Rollback**: host-thread model and wall-clock time (section 4) are design work, not blockers for a boot.

**Realistic first milestones**: (1) `xbe_symbols` + `xbe_recomp` on MKD with a clean stats file; (2) boot to the Midway logo and title (resolve "indirect call to X has no recompiled function" and "kernel export N not implemented" from `logs\`, adding `[[function]]` entries); (3) offline Arcade/VS fight with two SDL pads and audio; (4) same config path for MKA; (5) MKDA after the 4721 set; (6) frame hook + pad injection + arena snapshot prototype on the headless harness.
