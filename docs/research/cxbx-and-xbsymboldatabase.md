# Cxbx-Reloaded and XbSymbolDatabase: naming our XDK functions, and HLE semantics as reference

Research note, 2026-10-24. Sources: `external/XbSymbolDatabase` @ `20eced5` (2025-08-23, "d3d-oovpa-updates"), shortened to `X/`; `reference/Cxbx-Reloaded` @ `585c49a` (2026-04-19), shortened to `C/`. Both shallow clones, read as data; nothing was built. The three XBEs under `orig/` were read with a 40-line header parser (XBE header offsets from `X/include/Xbe.h:81-136`), not with the database.

**Our XBEs (facts from the headers).** MK:DA `orig/mkda-rev1/default.xbe` title 0x4D57000C, every library 1.0.**4721**.1: XAPILIB, D3D8, D3DX8, DSOUND, XBOXKRNL, LIBCMT, XMV (no XGRAPHC, no XONLINE). MK:D `orig/mkd/default.xbe` title 0x4D570019, all 1.0.**5849**: XAPILIB, D3D8, D3DX8, XGRAPHC, XBOXKRNL, XONLINES (QFE 7), LIBCMT, LIBCPMT, DSOUND, XVOICE (QFE 4), VOICMAIL. MK:A `orig/mka/default.xbe` title 0x4D570034 (internal name "Mortal Kombat 7"), same set at 5849 with D3D8 QFE 15, XGRAPHC QFE 9, XONLINES QFE 17, DSOUND QFE 11. All retail XBEs, base 0x00010000, with the usual `.text`, `D3D`, `D3DX`, `XGRPH`, `XNET`, `XONLINE`, `DSOUND`, `XPP`, `.rdata`, `.data` sections.

## 0. Answer first

- **4721 and 5849 are both inside the database's range.** Revisions run 3911..5849 (`X/src/OOVPADatabase/D3D8/*.inl` ends at `5849.inl`; `XOnline/5849.inl`, `Xapi/5455.inl`, `DSound/5558.inl`, `XGraphic/4361.inl`). Matching is "every revision with Version <= the XBE's library build" and the last hit wins (`X/src/lib/internal_functions.h:486-516`), so a title only needs a revision at or below its build. The maintainers verified exactly our builds on other games: 4721 Terminator: Dawn of Fate 202/227 D3D8 (`X/src/OOVPADatabase/D3D8_OOVPA.c:16`), 41/48 XAPI (`Xapi_OOVPA.c:16`), DSOUND full (`DSound_OOVPA.c:21`); 5849 Nickelodeon Tak 2 210/229 D3D8 (`D3D8_OOVPA.c:29`), 40/50 XAPI (`Xapi_OOVPA.c:27`), DSOUND full incl. Def Jam FFNY (`DSound_OOVPA.c:36-37`); XONLINE 5849 on nine titles (`XOnline_OOVPA.c:28-36`). QFE numbers are ignored except the 5558-5659 window (`X/src/lib/libXbSymbolDatabase.c:629-642`), so MK:A's D3D8 5849.15 is scanned as 5849.
- **Not covered:** D3DX8 (flag exists, no table; `X/projects/libXbSymbolDatabase/CMakeLists.txt:19`), LIBCMT/LIBCPMT, XMV, XVOICE, VOICMAIL (unknown names are skipped, `X/src/lib/libXbSymbolDatabase.c:579-582`), and XBOXKRNL (imports via the kernel thunk, not code).
- **We can run it today, no emulator needed.** The repo ships a C11 CLI (`X/src/cli/main.c`) that takes a raw `default.xbe` and prints `LIB__Symbol = 0xADDR`. Steps in section 1.5.

## 1. XbSymbolDatabase

### 1.1 What it is
An OOVPA ("Optimized Offset-Value Pair Array") signature database, the HLE database Caustik wrote for Cxbx, revised by RadWolfie, jarupxx and PatrickvL (`X/README.md:5-14`). A signature is a short header (`XRefCount`, `DetectSelect`, `Count`) followed by `{offset, byte}` pairs; the leading pairs may instead be `{offset, XREF index}` which require that a call/reference at that offset point at an already-found symbol (`X/src/OOVPADatabase/OOVPA.h:57-102`, `:126-134`). Each symbol is an `OOVPATable` row: xref id, scan type (manual/auto), symbol type (function/variable/internal), name, calling convention, parameter list, and an array of `(OOVPA*, Version)` revisions (`OOVPA.h:195-228`, `:244-269`). Names are generated by `SYM_FUN/SYM_VAR/SYM_FUN_LTCG` and carry stack-size and LTCG register suffixes, e.g. `D3DDevice_Swap_0__LTCG_eax1` (`OOVPA.h:402-409`; `X/src/OOVPADatabase/D3D8LTCG/4721.inl:4-8`). One `.inl` file per XDK build holds the signatures (`D3D8/5849.inl:1-30` shows a 5849 `D3DDevice_SetRenderState_StencilEnable` with two XREFs).

### 1.2 Libraries, tables, sections scanned
`X/src/lib/libXbSymbolDatabase.c:141-190` maps library flags to the sections it scans and the table: D3D8 and D3D8LTCG -> `.text`, `D3D`; DSOUND -> `DSOUND`, `.rdata`, `.text` (manual) ; XAPILIB -> `.text`, `XPP`; XGRAPHC -> `.text`, `XGRPH`; XONLINE/XONLINEN/**XONLINES**/XONLINLS -> `.text`, `XONLINE`, `XNET` (XONLINE table) and also the XNET table (`:184`, `:190`). Table sizes (`REGISTER_OOVPAS` rows): D3D8 266, D3D8LTCG 202, DSound 347, Xapi 97, XOnline 14, XNet 12, XGraphic 12, XActEng 23, JVS 65. Cross-reference ids: 388 (`X/include/xref/list_xref.h`), 315 D3D8 / 354 DSound / 106 XAPI lines in `X/include/xref/*.def`. XGRAPHC is only `XGSwizzleRect/Box`, `XGUnswizzle*`, `XGSet*Header`, `XGIsSwizzledFormat`, `XGCompressRect`, `XGWriteSurfaceOrTextureToXPR`, `XFONT_OpenBitmapFontFromMemory`. XONLINE is `XOnlineLogon`, `XOnlineMatchSearch*`, `XOnlineMatchSession{Create,Update}`, `XoUpdateLaunchNewImageInternal` plus their `CXo_` thiscall internals (`XOnline_OOVPA.c:62-89`); XNET is `XnInit`, `WSAStartup`, `XNetStartup`, `XNetGetEthernetLinkStatus`, and the thiscall `socket/bind/connect/listen/send/recv/ioctlsocket` (`XNet_OOVPA.c:33-57`). XAPI includes the full XID set (`XInitDevices`, `XGetDevices`, `XGetDeviceChanges`, `XInputOpen/Close/Poll/GetState/SetState/GetCapabilities`), `XLaunchNewImageA`, `XGetLaunchInfo`, `QueryPerformanceCounter`, `CreateThread`, fibers, `XMountUtilityDrive` (`X/include/xref/xapilib.def:32-96`; e.g. `XInputGetState` revisions 3911/4242/5455 at `Xapi_OOVPA.c:543-544`).

Beyond signatures there is a **manual scan** (`XbSDBContext_ScanManual`) that derives data symbols by walking code: `D3D_g_pDevice`, the per-version `D3DRS_*` render-state array offsets, `D3DDevice__m_{Swap,VBlank}Callback_OFFSET`, `m_VerticalBlankEvent_OFFSET` (`X/src/lib/manual_d3d8__ltcg.h:319-665`), the XAPI `g_DeviceType_*` globals and `XGetSectionSize` (`X/src/lib/manual_xapilib.h:8-265`), DSOUND vtables (`manual_dsound.h:8`).

### 1.3 Version selection in detail
`XbSDB_GenerateLibraryFilter` reads the XBE library-version table (`X/include/Xbe.h:81-91`) and emits one filter per known library with its build (`libXbSymbolDatabase.c:550-674`); DSOUND is added from the section name when the library entry is missing (`:648-659`). For each symbol the scanner tries all revisions, skipping any whose Version is above the XBE's build unless `XbSDBContext_SetBypassBuildVersionLimit` is set (`internal_functions.h:489-491`; `libXbSymbolDatabase.c:956-962`), warns on duplicate hits (`:499-503`) and keeps the last match. So MK:DA at 4721 is served by <=4721 revisions (D3D8 has no `4721.inl` but has 4627/4531/4034 for e.g. `D3DDevice_Swap`, `D3D8_OOVPA.c:597-598` `SYM_SIG(4034, 4531, 4627)`), and MK:D/MK:A at 5849 by <=5849 (XAPI tops out at 5455, DSOUND at 5558, which is why the two 5849 titles verify at 100%).

### 1.4 Public API, CLI, output, build, licence
- **API** (`X/include/libXbSymbolDatabase.h`): flags `XBSDBLIB_*` (`:58-79`); register callback `xb_symbol_register_t(library, flag, xref, name, address, build, symbol_type, call_type, param_count, params)` (`:225`); the staged API `XbSDB_GenerateLibraryFilter` -> `XbSDB_GenerateSectionFilter(is_raw)` -> `XbSDB_GetKernelThunkAddress` -> `XbSDB_CreateContext` -> `XbSDBContext_ScanManual` -> `XbSDBContext_ScanAllLibraryFilter` (or per-library `ScanLibrary`, thread-safe) -> `RegisterXRefs` -> `Release` (`:314-397`); legacy one-shot `XbSDB_Scan(header, cb, is_raw)` (`:228-234`); `XbSDB_LibraryVersion()` is a hash of the whole database used to invalidate caches (`:183`; `X/src/lib/internal_db_version.h:62-69`). `is_raw=true` scans a file image, `false` scans a loaded Xbox address space; addresses returned are always Xbox virtual addresses.
- **CLI** `XbSymbolDatabaseCLI xbefile [-v] [-d] [-e]` (`X/src/cli/main.c:87`): loads the file, checks `XBEH`, builds filters with `is_raw=1`, scans (`:103-178`). Output on stdout, one line per symbol: default `D3D8__D3DDevice_Swap = 0x00123456`; `-e` adds type/convention/params: `D3D8__FUN__stdcall__D3DDevice_Swap(psh Flags) = 0x...` or `D3D8__VAR__D3D_g_pDevice = 0x...` (`:16-61`); `-d` prints the canonical xref name instead of the versioned name (`:27`); `-v` sends the database's warnings (duplicate/too-high signatures) to stderr (`:11-14`, `:128-130`).
- **Build**: CMake >= 3.10.2, plain C11, static lib + CLI, no third-party dependencies (`X/CMakeLists.txt:42-44`; `X/projects/libXbSymbolDatabase/CMakeLists.txt:5,55,72`; `X/projects/cli/CMakeLists.txt:5-11,21`). Only the optional unit test (C++, `-DXBSDB_BUILD_UNITTEST=OFF`) fetches simpleini and xxHash (`X/projects/UnitTest/CMakeLists.txt:30-57`). CI builds win x86/x64, linux, macOS and publishes `XbSymbolDatabase.zip` containing `<platform_arch>/bin/XbSymbolDatabaseCLI[.exe]` plus `lib_static/` and `include/` (`X/.github/workflows/ci.yml:83-99,144-151`; `release.yml:32-37`). Latest GitHub release: v3.1.160 (2024-06-17, one asset `XbSymbolDatabase.zip`, 2.4 MB); a v4.0.166 pre-release exists; our checkout (2025-08) is newer than v3.1.160.
- **Licence**: code is MIT (`X/LICENSE`; `X/include/libXbSymbolDatabase.h:1`), but the signature tables themselves are **ODbL-1.0** (`X/src/OOVPADatabase/D3D8_OOVPA.c:1`, `OOVPA_databases.h:1`): attribution and share-alike apply if we redistribute a derived database.

### 1.5 Exact way to run it against our XBEs
Prebuilt (fastest): download `https://github.com/Cxbx-Reloaded/XbSymbolDatabase/releases/download/v3.1.160/XbSymbolDatabase.zip`, extract, then
`win_x64\bin\XbSymbolDatabaseCLI.exe orig\mkd\default.xbe -e -v 1> docs\research\symbols\mkd.txt 2> docs\research\symbols\mkd.log` (same for `orig\mka` and `orig\mkda-rev1`).
From our checkout (newer tables): `cmake -S external\XbSymbolDatabase -B build\xbsdb -A x64 -DXBSDB_BUILD_UNITTEST=OFF`, `cmake --build build\xbsdb --config Release`, `cmake --install build\xbsdb --config Release --prefix build\xbsdb\out` -> `build\xbsdb\out\bin\XbSymbolDatabaseCLI.exe` (install layout from `ci.yml:144`). Expect filters XAPILIB+D3D8+DSOUND for MK:DA and XAPILIB+D3D8+XGRAPHC+XONLINES(+XNET table)+DSOUND for MK:D/MK:A; `-v` lists them (`main.c:143-148`). The Xbox addresses in the output are directly usable as Ghidra labels (`createLabel`/`createFunction` from a 10-line Ghidra Python script over the `NAME = 0xADDR` lines).

## 2. Cxbx-Reloaded execution model

Cxbx-Reloaded (GPL-2.0, `C/COPYING`; Windows x64 or Wine only, `C/README.md:10`) is a **direct-execution HLE emulator**: the XBE's x86 code runs natively in a 32-bit WOW64 process laid out like an Xbox, kernel exports are host C++ functions, and selected XDK library functions found by XbSymbolDatabase are hooked with host implementations.

### 2.1 Loader and address space
`cxbxr-ldr.exe` is a CRT-less x86 EXE linked `/BASE:0x00010000 /FIXED /LARGEADDRESSAWARE` whose first global is a 128 MiB BSS placeholder so nothing else lands in Xbox user space (`C/src/loader/cxbxr-ldr.cpp:36-52`, `:78-86`). It refuses non-WOW64 hosts and non-64 KiB allocation granularity (`:146-171`), reserves every Xbox range (`:173-184`), then `LoadLibrary("cxbxr-emu.dll")` and calls `Emulate()` (`:186-220`). Ranges (`C/src/common/AddressRanges.h`): user 0x00010000-0x07FFFFFF (`:36-42`), contiguous/physical map 0x80000000 (+64 MiB retail, 128 MiB Chihiro, `:48-64`), devkit 0xB0000000, page tables 0xC0000000, system 0xD0000000, tiled 0xF0000000 (`:66-88`), NV2A 0xFD000000, APU 0xFE800000, AC97, USB, NVNet, flash (`:90-129`), `XBE_IMAGE_BASE 0x00010000` (`:132`). The XBE header is copied to its own base and every section is `XeLoadSection`-ed to its original virtual address (`C/src/core/kernel/init/CxbxKrnl.cpp:461-479`; `C/src/core/kernel/exports/EmuKrnlXe.cpp:63-103`), then the entry point is called like a function (`CxbxKrnl.cpp:134-139`).

### 2.2 Kernel
All 379 kernel thunk slots resolve to a host function or exported variable (`C/src/core/kernel/exports/KernelThunk.cpp:44-47` onward); the XBE's XOR-encoded thunk table is overwritten in place with host pointers (`CxbxKrnl.cpp:1192-1197`, `:329-345`). Implementation lives in `EmuKrnl{Av,Dbg,Ex,Fs,Hal,Io,Ke,Ki,Mm,Nt,Ob,Ps,Rtl,Xbox,Xc,Xe}.cpp` plus a real VM/physical-memory manager (`C/src/core/kernel/memory-manager/`). Roughly 97 `LOG_UNIMPLEMENTED/INCOMPLETE/NOT_SUPPORTED` marks remain, concentrated in Io (20), Av (17), Ke (15), Nt (15); Mm, Ob, Ps, Rtl, Xe are essentially complete. The project tests it against a hardware kernel test suite (`C/README.md:120`).

### 2.3 HLE patching driven by the symbol database
`EmuHLEIntercept` computes library flags from the XBE header (`C/src/core/hle/Intercept.cpp:333-385`), looks for a cache `%APPDATA%\Cxbx-Reloaded\SymbolCache\<title>-<xbeheaderhash>.ini` with sections `[Info] SymbolDatabaseVersionHash`, `[Certificate]`, `[Libs]`, `[Symbols] name=0xaddr` (`:57-78`, `:394-409`, `:415-462`, `:506-534`), otherwise calls `XbSDB_Scan(header, EmuRegisterSymbol, false)` on the loaded image (`:498-500`), stores every symbol in `g_SymbolAddresses` (`:210-298`) and installs patches. The patch table maps symbol name -> host function + flags `PATCH_HLE_D3D/DSOUND/OHCI/ALWAYS/IS_FIBER` (`C/src/core/hle/Patches.cpp:43-55`, `:60`): 343 active entries (29 commented out). Installation is a subhook inline hook per symbol, skipped when the matching LLE is on, with a per-title fiber exception list (`Patches.cpp:479-519`, `:446-475`); trampolines to the original Xbox code are kept for 62 D3D functions that Cxbx calls *through* (`C/src/core/hle/D3D8/Direct3D9/Direct3D9.cpp:318-374`, `Patches.cpp:541-554`).

### 2.4 D3D8 HLE and the pushbuffer
Patched D3D8 (`Patches.cpp:61-222`): `Direct3D_CreateDevice`, `D3DDevice_Reset`, all `Draw*` (Vertices/IndexedVertices/UP/RectPatch/TriPatch), `Begin/End` immediate mode, `Clear`, `CopyRects`, `Swap`/`Present` (`Present` forwards to `Swap`, `Direct3D9.cpp:5349`), `SetRenderTarget`, `SetTexture`, `SwitchTexture`, `SetPalette`, `SetStreamSource`, `SetIndices`, `SetTransform`, `SetMaterial`, `LightEnable`, `SetPixelShader`, vertex shader create/load/select/`SetVertexShaderConstant*`, `SetRenderState_Simple`, `SetVertexData2f/4f/4ub`, `RunPushBuffer`, `BeginPush/EndPush`, fences/`BlockOnFence`/`IsBusy`, visibility tests, `GetBackBuffer*`, `Lock2D/3DSurface`, `D3D_DestroyResource`, `CDevice_SetStateUP/VB`. Everything else in the Xbox D3D8 library runs natively: `SetRenderState_*`/texture-state setters write the Xbox-side `D3D__RenderState` and deferred texture-state arrays, which the HLE reads back via the database's `D3D_g_RenderState` / `D3D_g_DeferredTextureState` variables with per-XDK-version offsets (`C/src/core/hle/D3D8/Direct3D9/RenderStates.cpp:37-62`). The host side is Direct3D 9 (`g_pD3DDevice`, `Direct3D9.cpp:2230-2246`), with Xbox vertex/pixel shaders recompiled to HLSL (`XbVertexShader.cpp`, `XbPixelShader.cpp`, `C/import/nv2a_vsh_cpu`) and texture/format conversion in `XbConvert.cpp`. Pushbuffers: the XQEMU-derived NV2A model is always instantiated (`C/src/devices/video/nv2a.cpp:24-25`, PFIFO pusher/puller threads `:1225-1234`); the game's own writes to NV2A `USER` registers fault and are decoded by the x86 exception handler into MMIO (`C/src/core/kernel/support/Emu.cpp:249-293`; `C/src/devices/x86/EmuX86.cpp:190-238`; `EmuNV2A_USER.cpp:99-114`), and `D3DDevice_RunPushBuffer`/`EndPush` feed `EmuExecutePushBufferRaw`, which runs the LLE `pgraph_handle_method` with HLE draw callbacks (`C/src/core/hle/D3D8/XbPushBuffer.cpp:64-90`, `:253-262`, `:342-370`); `draw_arrays` and `inline_buffer` are still unimplemented (`:126-141`). Full LLE GPU (OpenGL) exists but is off by default (`CxbxKrnl.cpp:237-249`, `Intercept.cpp:306-312`).

### 2.5 DSound, XAPI/XInput, XOnline
DSound: 189 `EMUPATCH`es across `C/src/core/hle/DSOUND/DirectSound/*.cpp` onto host DirectSound 8 (`IDirectSound_CreateSoundBuffer/Stream`, 3D listener, mixbin headroom, effect-image/DSP data, `XAudio*`, `Patches.cpp:223-359`; DSP/I3DL2 handling noted at `DirectSound.cpp:560-666`). XAPI: only XID input (`XInitDevices`..`XInputSetState`, flag `PATCH_HLE_OHCI`, `Patches.cpp:361-373`), fibers, `SignalObjectAndWait`, MU mounting, `OutputDebugStringA` (`:375-393`); `XInputGetState` copies the host-polled XID packet into `XINPUT_STATE` and bumps `dwPacketNumber` (`C/src/core/hle/XAPI/Xapi.cpp:434-452`, `:711-731`); LLE USB is disabled (`CxbxKrnl.cpp:1133`). XOnline/XNet: **no HLE at all** (`C/src/core/hle/XONLINE/XOnline.h:25` is `#if 0 // XOnline.h isn't used`); the XNET stack in the XBE runs natively against an LLE NVNet NIC bridged to a real adapter through Npcap (`C/src/devices/network/NVNetDevice.cpp:45,617-710`; `C/README.md:18-19`), i.e. System Link works only by raw Ethernet bridging and Xbox Live logon cannot succeed.

### 2.6 Threads and time
`PsCreateSystemThreadEx` creates a real Win32 thread per Xbox thread (`_beginthreadex`, `C/src/core/kernel/exports/EmuKrnlPs.cpp:393`) with an Xbox-side ETHREAD/KTHREAD and stack, pinned by an affinity policy that keeps all Xbox threads on one core unless the "all cores" hack is on (`:412`; `C/src/common/win32/Threads.cpp:197-245`; `CxbxKrnl.cpp:1155-1158`). Waits/delays are Xbox-side wait blocks on top of host `NtDelayExecution` with a precise host sleep (`EmuKrnlKe.cpp:747-805`). Clocks: a host `system_events` thread advances `KeInterruptTime`, `KeSystemTime`, `KeTickCount` and expires timers from `QueryPerformanceCounter` (`C/src/common/Timer.cpp:54-66,128-175`; `EmuKrnlKi.cpp:149-211`); `KeQueryPerformanceCounter` is host QPC rescaled to the 3.375 MHz ACPI clock, `rdtsc` is byte-patched to a privileged opcode and emulated at 733.33 MHz (`EmuKrnlKe.cpp:545-552,1479-1498`; `C/src/core/kernel/support/PatchRdtsc.cpp:40-61,100-110`; `EmuX86.cpp:1302-1306`). VBlank is a 16.67 ms host-timer event that bumps `g_Xbox_VBlankData` and fires the title's vblank callback (`Direct3D9.cpp:1928-1960`; `nv2a.cpp:1111-1130,1218-1223`); `D3DDevice_Swap` presents, applies a frame limiter from the Xbox presentation interval, then calls the title's swap callback (`Direct3D9.cpp:5379-5416`, `:5649-5696`, `:5719-5727`).

### 2.7 Savestates, netplay, MK compatibility
No savestate/snapshot code or plan exists in the tree (only "snapshot" hits are a pixel-shader helper and PerfTrace). No netplay/System Link emulation beyond the pcap NIC. No MK-specific data: the only Midway reference is SpyHunter 2 `[4D57001B]` as a pushbuffer test case (`XbPushBuffer.cpp:108,360`); per-title hacks are limited to the fiber list (`Patches.cpp:457-461`) and global hacks (`C/src/common/Settings.hpp:179-194`). Compatibility status is kept on the project website, not in the repo.

## 3. Reusable assets for the native port
1. **XbSymbolDatabase CLI output** as the authoritative XDK symbol list per XBE: seed Ghidra names (functions *and* the derived globals `D3D_g_pDevice`, `D3D_g_RenderState`, `g_DeviceType_*`), and diff against XboxXBERecomp's signature matches (same symbol vocabulary; watch the `_N`/`__LTCG_reg` suffix conventions, `OOVPA.h:402-409`).
2. **Ghidra loader**: mborgerson/ghidra-xbe (`https://github.com/mborgerson/ghidra-xbe`) loads XBEs and, per its README, does "library symbol recovery ... through integrated pattern matching against the XbSymbolDatabase"; installed as the `XboxExecutableLoader` extension, built with its `build.sh`. Licence not stated in the README; check the repo before depending on it. Cxbx's own `C/doc/development/IDA-MissedHLF.txt` and the `C/doc/*.7z` Dxbx/D3D8LTCG IDA pattern archives are a second cross-check source.
3. **Kernel reference**: `C/src/core/kernel/exports/EmuKrnl*.cpp` documents the semantics our recompiled XAPI/LIBCMT code will expect from `xboxkrnl` (timer/APC/wait rules in Ke/Ki, `NtCreateFile` path mapping in Nt/Io/EmuFS, `XeLoadSection`, frequencies at `EmuKrnlKe.cpp:545-546`).
4. **D3D8 semantics**: `Direct3D9.cpp` + `RenderStates.cpp`/`TextureStates.cpp`/`XbState.cpp` (what each Xbox call mutates, version-gated render-state layout), `XbVertexShader.cpp`/`XbPixelShader.cpp` (Xbox shader formats), `XbConvert.cpp` (texture formats, swizzling), `XbPushBuffer.cpp` (pushbuffer/fixup encoding `:78-87`), `C/import/OpenXDK` headers.
5. **DSound semantics**: `C/src/core/hle/DSOUND/` (mixbins, XADPCM, DSP effect images, stream packet manager) and `common/XbInternalStruct.cpp` for the Xbox-side object layouts.
6. **XInput/XID**: `Xapi.cpp:434-831` (device enumeration masks, 20-byte XID packet + header, `dwPacketNumber` semantics) and `C/src/common/input/` for host mapping.

## 4. Rollback angle: could a Cxbx-Reloaded fork be the emulator track?
- **Determinism**: game code executes natively (good), but everything around it is host-timed: Win32 threads under the Windows scheduler, timers and vblank from host QPC on a separate thread, `rdtsc`/QPC rescaled from host time, DSound driven by host buffers. Two runs with identical inputs will not take identical paths unless every clock source (`Timer.cpp:128-139`, `EmuKrnlKi.cpp:149-211`, `EmuX86.cpp:1302-1306`, `hle_vblank`) is replaced by a frame-stepped virtual clock and the Xbox threads are serialized.
- **Snapshot**: Xbox-visible memory is contiguous host memory at fixed addresses (section 2.1) and the VM manager can enumerate it (`C/src/core/kernel/memory-manager/VMManager.h`), so memory can be copied. But thread state lives in native threads that may be blocked inside host syscalls (`EmuKrnlKe.cpp:785-797`), kernel objects are backed by Win32 handles (`C/src/core/kernel/support/NativeHandle.cpp`), and HLE caches (D3D9 resources, shader caches, `ResourceTracker.cpp`, DirectSound buffers) are host objects with no serializer. Nothing like RPCS3's savestate framework exists; building one means rewriting threading and all HLE state ownership.
- **Frame boundary**: good. `D3DDevice_Swap` (`Direct3D9.cpp:5379`) is one hook per frame and already owns the frame limiter and swap callback; vblank would have to be generated from the same loop instead of the timer thread.
- **Input injection**: easy. Replace the `UpdateXboxPortInput` fill in `CxbxImpl_XInputHandler` (`Xapi.cpp:442-449`) with the netplay-provided XID state per port.
- **Practical blockers**: no savestates; non-deterministic threading/timing by design; host-side HLE state; a WOW64-only, fixed-layout 32-bit process; GPL-2.0 on the whole emulator for a shipped product; unknown MK accuracy. Verdict: not a viable rollback track; the xemu study covers the emulator that does have snapshots.

## 5. Recommended uses
